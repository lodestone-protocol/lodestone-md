# ADR-0002 一致性语料与性能策略（P2 生态对齐）

> **状态**：Active（2026-09-02）
> **关联**：P2 T1（fixture §来源 清单）、T2（性能验证）、T3（观察项 γ 登记）
> **方法论**：phyt-DNA v1.0

---

## 背景

P2 目标有三：把 Golden Fixture 提升为可独立发布的跨实现一致性语料；验证解析性能并评估附录 A 的启发式快速扫描（L1-only）路径；登记协议 v2.0 议程观察项。

## 决策

| 决策点 | 决议 | 放弃的方案 |
|---|---|---|
| fixture 章节来源标注 | **集中清单** `tests/fixtures/MANIFEST.md`（fixture ↔ 规范章节双向索引，14/14 码覆盖率表） | 各 fixture 头部内联注释（会改变解析字节，破坏 golden 稳定性） |
| MANIFEST 不被误食 | golden 扫描器显式排除 MANIFEST.md | 命名避开 .md |
| 性能策略 | **全量单趟解析即 L1**：`parse()` 天然产出 L1 骨架，先测量后优化；**暂不引入**启发式双路径 | 双路径快速扫描（§9 可选的 L1-only 优化，徒增双实现漂移面） |
| 基准 | `examples/bench.rs`（合成 N 节点链，release 模式粗粒度体检），非 CI 门槛 | criterion 依赖（确定性优先 + 极致解耦，不入测试依赖） |
| 观察项 γ 登记 | 记录于本 ADR 第五节，供协议 v2.0 复查 | 开 ISSUE（仓库尚无 issue 模板治理） |

## 理由

- **集中清单 vs 内联头注释**：fixture 是解析字节的黄金基准，任何头部内容都会改变节点/正文派生值（实测一改全表变）。内联标注 = 用语料稳定性换可读性，违背确定性优先。
- **不引入启发式双路径**：附录 A 的快速扫描仅省一次 comrak 解析；本项目 parse() 单趟已达线性，双路径意味着"快路径 / 慢路径必须输出一致"这一永久一致性负担（两套实现、两套 fixture），与极致复用/极致解耦相悖。若未来实测 L1 成为瓶颈再以新 ADR 引入。
- **bench 非 criterion**：criterion 的统计采样入 CI 会制造时间抖动噪声，与确定性优先的精神相左；合成大文档的粗粒度体检已足够回答"数量级是否正确"。

## 后果

- fixtures/ 现由 MANIFEST.md 索引，可整体拷贝作为其他实现的验证语料（验证器一致性类对齐 §11 码）；
- 无启发式路径，因此"启发式与全量在含围栏文档上一致"的验收标准（PLAN P2 T2）**不适用**，P2 T2 验收改为：bench 报告 + 不引入双路径的决议；PLAN 已同步修订；
- 观察项 γ 收集口径：登记"derive 在真实文档中的声明频率 / 误用率"，v2.0 复查其转置语法糖价值。

---

## 五、观察项 γ 登记（v2.0 议程 · 协议附录 C）

- **内容**：derive 作为 depend 的转置书写糖，实际误用率若偏高，v2.0 复查其存在价值。
- **本仓库立场**：derive 与 depend 持久化格式均合法（§7.2），解析输出一律折叠为 depend 方向，因此**语料不因书写形式而异**——误用率影响的是作者体验而非解析正确性。建议 v2.0 收集真实文档中 `relation:"derive"` 的占比作为观测指标。
- **状态**：观察中（无数据源，等待生态使用）。

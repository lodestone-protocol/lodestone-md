# 哲学公理卷（philosophy）

> **锚定**：VISION 原子原则 1–8 全部
> **性质**：白皮书分卷。按任务加载，禁止一次性加载全部。

---

## 公理一：确定性优先

解析结果是文档当前字节的纯函数。推论：

1. 解析器不得持有跨调用可变状态；
2. 输出结构体的字段顺序、序列化顺序必须固定；
3. 依赖版本锁定（Cargo.lock 入库）是确定性的工程延伸；
4. `aligned` 不是内容指纹——字节稳定性由协议外机制（VCS）负责，消费方不得假定。

## 公理二：机器按需优先

协议的原生消费方是 AI agent，原生读取模式是三级加载：

| 级 | 内容 | 典型任务 |
|---|---|---|
| L1 骨架 | 节点表 + 规范化边集合 + 诊断列表 | 重建全局认知、规划读取 |
| L2 定点正文 | 按 body_start/body_end 读取 | 回答具体问题、追溯依赖 |
| L3 全文 | 全部字节 | 查全率任务（审查/迁移/审计） |

L1/L2 遗漏是策略性取舍；L3 查全率是消费方对确定性任务的义务。降级路径 L1→L2→L3 永远可用。

## 公理三：结构零干扰

元数据以 HTML 注释承载，其渲染透明性由 CommonMark 规范本身保证。元数据不产生标题、不进入大纲、不构成渲染输出。源码中的可见性是人类的审计通道，属中性考量。

## 公理四：行为钉死

规范对每种失败情形给出唯一既定行为（"全部失败路径收敛于警告 + 继续解析"或"节点无效"）。实现不得引入规范之外的分支自由度；遇到规范歧义，先查原文，再以 ADR 记录解释决议。

## 公理五：容错分层

形态层 → JSON 层 → 字段层，失败后果逐层递减（节点无效 → 节点无效 → 字段降级）。无效节点保留占位（含标题、invalid 标注），MUST NOT 被引用、不参与图计算、不参与 E-DUP-ID 检测。

## 公理六：延迟绑定

一条规范化边仅当双端均为 `aligned` 且通过全部校验时才进入全局图。局部结论在收敛前不污染全局结构。`aligned` 是作者的社会契约断言，非物理不可变证明。

## 公理七：测试即规范之镜

每条 MUST/SHOULD 至少一个 Golden Fixture 对应，fixture 头注释标注规范章节来源。§10 完整示例的节点表数值（chars、body 区间）逐项断言——它是规范内置的黄金基准。

## 公理八：版本边界

本实现只实现 v1.3 正文；附录 C（v2.0 议程：哈希、跨文档引用、CRDT 合并等）不进入代码，不预留悬空接口。范围限定：单文档作用域。

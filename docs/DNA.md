## 一、不可变原则（公理）

见 `docs/VISION.md` 原子原则表与哲学七律（逻辑闭环 / 极致复用 / 极致解耦 / 按需获取 / 按需加载 / 物理实时优先 / 确定性优先）。本文件定义**工程映射**与**防腐化铁律**。

**工程映射（关键原则的可验证落地）**：

| 原则 | 工程映射 | 验收标准 |
|---|---|---|
| 确定性优先 | 解析器无全局可变状态；输出结构体字段顺序固定；serde 序列化排序确定 | 同输入两次运行输出逐字节一致（CI 断言） |
| 行为钉死 | 规范 §3.1 行为表逐行映射为代码分支 + Fixture；无"尽力而为"分支 | §11 每个码至少一个 Fixture |
| CommonMark 锚定 | comrak 钉死版本（ADR-0001），AST 顶层块判定边界 | 围栏内 `#` 行不构成边界的 Fixture |
| 容错分层 | 三层校验为独立函数，失败后果由类型系统区分（valid 标志 + 降级值） | 每层失败路径 Fixture |
| 测试即规范之镜 | Golden Fixture 与规范章节双向引用（fixture 头注释标注 §来源） | PR 模板检查项 |

## 二、分层自纠偏系统（N/D/A）

| 层级 | 名称 | 形式 | 作用 |
|---|---|---|---|
| **N 层** | 叙事层（愿景） | `VISION.md` + `docs/SPEC.md` + `docs/spec/` | 顶层叙事，所有决策最终裁判 |
| **D 层** | 决策层（ADR） | `docs/decisions/ADR-*.md` | 记录架构决策的"为什么"与"放弃了什么" |
| **A 层** | 架构层（代码） | `src/` + `tests/` | 物理实现最终形态 |

## 三、文档生态 SOP

| 文档 | 职责 | 规则 |
|---|---|---|
| **PLAN.md** | 当前阶段导航 + 下一阶段预览 + 阶段总览 | ≤150 行，超出触发历史迁移 |
| **GROWTH.md** | 已完成阶段生长记录 | ≤3 条，超则归档至 `docs/archive/growth/` |
| **ADR** | 决策记录 | 两态（Draft/Active），Active 后不可覆写，仅可 Superseded |
| **归档** | 历史记录 | 随仓库版本化，永不删除 |

## 四、防腐化铁律（5 条，通用）

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **版本以 spec/代码为源真相** | README/门面标注必须对齐，防版本漂移 |
| 2 | **契约冻结不可静默修改** | 解析输出契约（§8.1–§8.4）为冻结接口；扩展走 Append-Only |
| 3 | **变更先 ADR（D 层冻结）→ 改代码 → 同步门面** | 决策先于代码 |
| 4 | **生长记录保留近 3 条，超则归档** | 历史永不删除，按需加载 |
| 5 | **提交前必须人工确认** | 无自动提交 |

## 五、项目特有铁律

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **规范文本至上** | 实现与规范 v1.3 冲突时，实现为错；疑义先查规范原文，再开 ADR 提议修订 |
| 2 | **警告非错误** | W-* 码绝不阻断解析、绝不改变节点有效性；E-* 码后果严格按 §11 |
| 3 | **不推断状态** | 解析器 MUST NOT 推断、修改或"纠正"节点 status（§6 约束 2） |
| 4 | **单一解析管线** | 所有输出（节点表/边/图/诊断）必须出自 §8 管线同一趟结果，禁止旁路计算 |
| 5 | **v2.0 议程隔离** | 附录 C 列出的机制（哈希、跨文档引用等）不进入 v1.x 代码，不预留悬空接口 |
